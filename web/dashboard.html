常驻监听与客户端接入

01 启用客户端事件，再重启客户端

Codex App 与 Codex CLI 需要启用观测启动参数，并重新启动，才能写出调用事件和原始响应事件。服务运行仅表示监听器已启动；顶部会分别显示两个客户端是否已接入。「待重启接入」表示当前没有已接入的客户端进程。

请求仍使用原有服务地址，无需更改客户端 base_url。客户端接入后，监听器常驻读取事件，无需手动开始或设置捕获时长。

02 Request 与 Response 自动配对

Request 来自客户端发送事件，Response 来自调用完成事件及原始响应事件。客户端生成的逻辑调用 UUID 标识同一次调用，服务端 response_id 关联响应生命周期；不按相近时间或相同会话猜测配对。

请求发出后显示「等待响应」；只有单侧证据时显示等待状态。一个聊天轮次可以触发多次调用，内部 HTTP 重试可能共用一个逻辑调用标识，因此记录数不等于网络请求包数或计费次数。

03 核对字段和来源

Codex App 与 Codex CLI 分开显示。Request 展示请求的模型与 reasoning.effort，Response 展示采集到的服务端回显。完成事件本身没有携带回显时标记「回显未采集」；原始响应明确未含档位时标记「未回显」，两者分别保留。

历史内存证据仍可查看，并标记「历史内存」。缺少调用标识的旧记录不会强行配对。

04 当前采集范围

观测依赖当前版本客户端提供的原生调用事件和响应事件。HTTP 与 WebSocket 的事件支持随客户端版本和实际连接路径而异；仅凭监听器运行不能保证所有网络包都已采集。出现读取错误时，顶部会显示错误信息。

响应字段表示服务端报告值，可以核对字段差异，不能直接测量模型内部的实际思考量。
