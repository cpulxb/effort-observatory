CLIENT EVENTS

常驻监听与历史会话

01 / 启用观测参数并重启客户端

Codex App 与 Codex CLI 需通过观测启动方式重新启动，才能写出调用与原始响应事件。 顶部分别显示监听器和客户端接入状态；服务启动不表示当前客户端已接入。 「待重启接入」表示没有仍在运行的已接入进程。

客户端仍使用原有服务地址，无需修改 base_url。接入后的事件会持续记录， 不需要开始按钮，也没有捕获倒计时。暂停页面自动刷新不会停止监听。

02 / 按调用自动配对

Request 来自客户端发送事件，Response 来自完成事件与原始响应事件。 两侧按客户端生成的逻辑调用 UUID 连接，响应生命周期按 response_id 合并。 内部 HTTP 重试可能共用同一个逻辑调用 ID，记录数不等于所有网络请求包或计费次数。

返回调用日志首页，按 Codex App / Codex CLI 查看并列的 Request / Response。 请求发出后显示等待响应；完成事件缺少服务端回显时显示「回显未采集」， 原始响应明确没有档位字段时显示「未回显」。

03 / 历史会话与证据关联

本页保留历史会话、消息与工具时间线，使用明确的 turn_id 或响应 output_id 关联消息。 历史内存证据可能只有会话 ID，缺少可靠消息标识，因此保留原始来源与关联说明， 不按时间强行归属。新的调用配对独立于消息时间线，直接在首页查看。 所有时间可切换 UTC；观测时间与服务端时间分别展示。

事件支持取决于客户端版本和连接路径；HTTP 与 WebSocket 需分别验证。 监听器运行不保证所有网络包都已采集。响应字段表示服务端报告值，不能直接测量模型内部计算量。
